# كاتب عمومي — Katib Oumoumi

تطبيق ويب (Single Page Application) بلغة JavaScript الخام (Vanilla JS)، بدون أي إطار عمل
(framework) وبدون خطوة بناء (build step)، يتصل مباشرة بـ Supabase، ويُنشر على GitHub Pages.

يولّد التطبيق وثائق إدارية مغربية (شكايات، توكيلات، عقود...) بصيغتي **Word** و **PDF**
انطلاقاً من قوالب يُعدّها المسؤول (Admin)، ويملؤها المستخدم العادي عبر نموذج ديناميكي.

## نوعا المستخدمين

- **مستخدم عادي** (بدون تسجيل دخول): يتصفح التصنيفات، يختار نوع الوثيقة، يملأ الحقول
  المطلوبة، ثم يولّد الوثيقة ويحمّلها (Word أو PDF) أو يشاركها. تُحفظ الوثائق المولَّدة
  محلياً في متصفحه ("سجل الوثائق").
- **المسؤول (Admin)**: حساب وحيد ومحدَّد مسبقاً، يسجّل الدخول عبر `#/admin/login`، وله
  لوحة تحكم لإنشاء/تعديل التصنيفات وأنواع الوثائق، وتعريف حقول كل قالب (placeholders)
  مع نوعها (نص قصير، نص طويل، رقم، تاريخ، هاتف، بريد إلكتروني، رقم البطاقة الوطنية).

## 1. إعداد Supabase

1. أنشئ مشروعاً جديداً على [supabase.com](https://supabase.com).
2. من **SQL Editor**، افتح استعلاماً جديداً وألصق محتوى الملف
   [`supabase/schema.sql`](supabase/schema.sql) بالكامل، ثم نفّذه. سيقوم هذا بـ:
   - إنشاء الجداول: `categories`, `document_types`, `template_fields`, `generated_documents`
   - تفعيل Row Level Security مع سياسات قراءة عامة (anon) وسياسات كتابة للمسؤول (authenticated)
   - إدراج بيانات أولية (Seed): التصنيفات وأنواع الوثائق
   ثم نفّذ بنفس الطريقة الملف [`supabase/templates.sql`](supabase/templates.sql)، الذي يضيف نصوص
   القوالب وحقولها (شكاية إدارية، شكاية بسبب الجار، وكالة عامة، عقد شغل، عقد كراء وفق القانون 67.12).
   هذا الملف قابل لإعادة التنفيذ دون أضرار: نفّذه أيضاً على قاعدة موجودة مسبقاً لتحديث القوالب.
3. من **Authentication → Providers**، تأكد أن **Email** مفعّل.
4. **مهم جداً — تعطيل التسجيل العام**: من **Authentication → Settings**، عطّل خيار
   "Allow new users to sign up" (Enable email signups). التطبيق لا يحتوي على واجهة تسجيل
   للمسؤول عن قصد؛ الحساب الوحيد يُنشأ يدوياً من طرفك.
5. أنشئ حساب المسؤول الوحيد من **Authentication → Users → Add user** (بريد إلكتروني
   وكلمة مرور من اختيارك). هذا هو الحساب الذي سيُستعمل لتسجيل الدخول إلى `#/admin/login`.
6. من **Project Settings → API**، انسخ:
   - `Project URL` → سيُستعمل كـ `SUPABASE_URL`
   - `anon public` key → سيُستعمل كـ `SUPABASE_ANON_KEY`

> ملاحظة أمنية: سياسات RLS في هذا المشروع تمنح صلاحية الكتابة الكاملة لأي مستخدم
> "authenticated" (وليس فقط لمستخدم محدد بمعرّفه)، على افتراض أن حساب المسؤول
> سيبقى الحساب الوحيد المسجَّل في المشروع (بما أن التسجيل العام معطَّل). إن احتجت لاحقاً
> إلى أكثر من مسؤول أو أردت تقييداً أدق، عدّل سياسات `admin full access ...` في
> `schema.sql` لتتحقق من `auth.uid() = '<UUID المسؤول>'` بدلاً من `auth.role() = 'authenticated'`.

## 2. النشر على GitHub Pages

1. أنشئ مستودع GitHub جديداً وارفع محتوى هذا المجلد إلى الفرع `main`
   (تأكد أن `index.html` و`.github/` موجودان في **جذر** المستودع مباشرة).
2. من إعدادات المستودع **Settings → Pages**، اختر **Source: GitHub Actions**.
3. من **Settings → Secrets and variables → Actions → New repository secret**، أضف:
   - `SUPABASE_URL`
   - `SUPABASE_ANON_KEY`
4. أي `push` إلى `main` سيُشغّل `.github/workflows/deploy-pages.yml` الذي:
   - يولّد ملف `supabase-config.js` من الأسرار أعلاه (`window.SUPABASE_CONFIG`)
   - ينشر محتوى المستودع بأكمله كموقع GitHub Pages

بعد نجاح أول عملية نشر، سيكون التطبيق متاحاً على الرابط الذي يظهر في تبويب **Actions**
أو في **Settings → Pages**.

## 3. التطوير المحلي

لا حاجة لأي أداة بناء (bundler) — الملفات HTML/CSS/JS تُقرأ كما هي. يكفي خادم ملفات ثابت:

```bash
# انسخ نموذج الإعداد وامْلأ بياناتك الخاصة بمشروع Supabase
cp supabase-config.example.js supabase-config.js

# ثم شغّل أي خادم ثابت بسيط، مثلاً:
python3 -m http.server 8080
# أو: npx serve .
```

ثم افتح `http://localhost:8080`. لاحظ أن `supabase-config.js` مُستثنى من Git
(`.gitignore`) — يُولَّد تلقائياً في الإنتاج عبر GitHub Actions.

## 4. بنية المشروع

```
index.html                     نقطة الدخول HTML
css/styles.css                 كل التنسيقات (متغيّرات الألوان، الشبكات، البطاقات...)
js/main.js                     تسجيل المسارات وتشغيل التطبيق
js/router.js                   موجّه بسيط قائم على الـ hash (#/...)
js/ui.js                       عناصر واجهة مشتركة: الترويسة، الشريط السفلي، Toast
js/api.js                      كل استعلامات Supabase (عامة + مسؤول)
js/session.js                  معرّف جلسة مجهول لكل متصفح
js/history.js                  سجل الوثائق (localStorage)
js/utils/
  icons.js                     أيقونات SVG مضمّنة
  format.js                    تنسيق التاريخ بالأشهر المغربية (يناير، غشت، دجنبر...)
  validators.js                أنواع الحقول والتحقق منها (هاتف مغربي، البطاقة الوطنية...)
  templateEngine.js            استبدال {{placeholders}} داخل نص القالب
  docGenerator.js              تصدير Word (html-docx-js) وPDF (jsPDF)
js/views/                      الشاشات: الرئيسية، التصنيفات، النموذج، الجاهزية، السجل، الإعدادات
js/admin/                       تسجيل دخول المسؤول، لوحة التحكم، إدارة التصنيفات والوثائق
supabase/schema.sql             مخطط القاعدة + RLS + بيانات أولية
supabase/templates.sql          نصوص القوالب وحقولها (قابل لإعادة التنفيذ)
.github/workflows/deploy-pages.yml   نشر تلقائي على GitHub Pages
```

## 5. كيف تعمل توليد الوثائق (تقنياً)

- كل **نوع وثيقة** (`document_types`) يملك:
  - `template_body`: نص HTML بسيط يحتوي على رموز مثل `{{اسم الموكل}}`
  - مجموعة **حقول** (`template_fields`) تحدد كل رمز: تسمية، نوع، إلزامي أم لا
- عند ملء المستخدم للنموذج، يُستبدل كل `{{مفتاح}}` بالقيمة المُدخلة (مع تنسيق خاص
  للتواريخ بالأشهر المغربية: يناير، فبراير، ...، يوليوز، غشت، شتنبر، ...، دجنبر).
- **Word (.docx)**: يُحوَّل HTML الناتج مباشرة إلى ملف Word عبر مكتبة `html-docx-js`
  (بدون خادم تحويل خارجي).
- **PDF**: يُصيَّر HTML الناتج داخل إطار مخفي معزول (مع تضمين خط Tajawal)، ثم يُرسم عبر
  SVG `foreignObject` — أي بمحرك المتصفح نفسه، مما يضمن تشكيلاً سليماً للعربية واتجاه RTL —
  ويُقسَّم إلى صفحات A4 بين الأسطر (دون قطع أي سطر) ويُجمَّع عبر `jsPDF`. إن رفض المتصفح
  ذلك (بعض إصدارات Safari)، تُفتح نافذة الطباعة لاختيار "حفظ بصيغة PDF".
- لا حاجة لتخزين ملفات (Supabase Storage) — القالب نص عادي محفوظ في قاعدة البيانات.

### ملاحظة حول "شاهد إعلاناً لتحميل الوثيقة"

شاشة "الوثيقة جاهزة" تُحاكي تدفق الإعلان القصير الموجود في النماذج المرجعية (عدّاد
تنازلي قصير قبل إظهار أزرار التحميل). هذا **بديل مؤقت** لأي شبكة إعلانات فعلية
(Google Ad Manager للويب مثلاً) — لدمج إعلانات حقيقية، استبدل الدالة
`runAdSimulation()` في `js/views/ready.js` باستدعاء SDK الإعلانات الفعلي.

## 6. إضافة أنواع وثائق جديدة

يمكن إضافتها إما عبر `supabase/schema.sql` (بيانات أولية إضافية)، أو — الطريقة
الموصى بها — عبر لوحة تحكم المسؤول: `#/admin` ← "وثيقة جديدة"، حيث تضيف الحقول
ونوع كل حقل، ثم تكتب نص القالب باستعمال نفس مفاتيح الحقول.
